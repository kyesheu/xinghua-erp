# 功能说明

系统面向多商户、多店铺的进销存业务，覆盖商品、订单、库存、采购、发货和经营分析。包含淘宝、拼多多、抖音、京东、快手、微信小店、小红书等平台的接入代码，各平台功能可用性取决于当前实现、应用权限及店铺授权。AI 能力见[AI 智能体说明](AI智能体说明.md)。

## 商品管理

- SPU/SKU 双层数据模型，类目与类目属性体系，品牌管理
- 平台店铺商品与内部 SKU 映射归集，订单/库存/统计统一按内部 SKU 口径
- AI 商品文案优化：标题、卖点、描述、关键词草稿与站点规则检查
- 商品列表、批量管理、商品分类、供应商与 SKU 供货关系

## 订单管理

- 多平台订单与售后定时增量拉取，幂等去重入库，拉取日志可查
- 订单审核、状态流转，支持一单多明细、部分发货等场景
- 退款/售后台账，退款与原单匹配核对
- 打单发货：手工发货、打印、电子面单账户、供应商代发、云仓发货
- 开启 MQ 后，平台新订单通过事务 Outbox 记录通知事件；后台确认投递、消费去重，失败消息进入死信队列。该链路用于通知，不代替库存与财务事务。

## 库存管理

- 多仓库、多库位管理，良品库存与订单锁定量分离
- 出入库单据流：采购入库、销售出库、调拨、盘点、领用
- 订单占用库存的锁定—释放—核销机制防止超卖
- 出库登记批次成本快照，支撑财务按结算口径核算利润
- AI 库存总览、补货估算与人机审核闭环

## 采购管理

- 采购单创建、审核、入库任务管理，未入库量按采购明细与实入台账核对
- 供应商档案、供应商报价、代发发货人管理

## 财务

- 已审核结算单利润核算：销售额 − 批次成本 − 运费 − 已审核费用单，单币种（人民币）
- 财务流水、费用单登记，平台账单导入
- AI 财务资料：订单级负利润穿透、多店对比

## 权限与系统管理

- RBAC 接口权限：用户、角色、菜单、字典管理
- 业务主体三级数据范围：总部 / 商户 / 店铺，账号经 `erp_business_user_binding` 绑定主体，服务端在 SQL 层拼接范围过滤，防止横向越权（详见 [业务账号权限与数据范围](业务账号权限与数据范围.md)）
- 系统消息与外部通知：飞书、钉钉、企业微信 Webhook 推送（详见 [消息与外部通知设计](消息与外部通知设计.md)）

## AI 智能体

LangGraph 工作流 + Java 权限门禁的双栈实现：自然语言经营分析（多主题并行）、SKU 表现排行、订单级亏损穿透、多店对比、明细导出、库存补货人工审核闭环。详见 [AI 智能体说明](AI智能体说明.md)。

## 商品拉取的部分成功与完整性

商品逐条保存失败时返回部分失败，保留已保存结果供重试核对，不把它报告成全量成功。拼多多商品按页读取，只有本次分页完成且保存均成功才更新成功拉取时间；分页提前结束、取消、超时或达到上限均明确未完成。单次最多检查500页，分页前检查90秒期限；已开始的网络调用仍受渠道客户端超时限制。重试需要依靠店铺商品业务标识去重，不会回滚此前已保存的页面。

淘宝商品分页不额外请求总页数之后的一页，后续页返回结构异常按未完成处理。上述行为不代表所有平台已经具有自动退避、断点恢复或完整同步能力，具体平台入口仍以实际实现和授权为准。

使用公共 OkHttpClientHelper 的渠道请求统一复用客户端，连接最多5秒、读取和写入最多20秒、整次请求最多30秒；响应最多8MiB。非成功HTTP状态或超过大小限制按失败处理。该封装关闭透明网络重试与自动重定向，业务侧必须根据平台语义决定是否重试；此设置不代表其他SDK封装已经采用相同边界。
