# AI 智能体说明

AI 智能体为商家提供自然语言经营分析与人机协同的补货审核，采用 **Java 权限门禁 + Python LangGraph 工作流**双栈实现。

## 职责边界

Java 负责业务数据和权限，Python 负责模型与工作流。Python 不直接访问 ERP 业务库；审核工作流可以访问自身的 SQLite 或 PostgreSQL 检查点存储。

| 环节 | 由谁负责 |
| --- | --- |
| 身份、权限、主体数据范围校验 | Java |
| 业务数据组装与只读查询 | Java（`ai-data` 只读接口 + 工具网关） |
| 模型构建、提示词、工具选择、多轮循环、流式输出 | Python（`ai-service`） |
| 服务不可用时的兜底 | Java（本地数据摘要 / 固定文案简报 / 可读提示） |

对话与分析都走同一条链路：前端 SSE → Java 组装上下文 → Python 调用模型并自行决定查什么 → Python 经工具网关回调 Java 取数 → 结果逐段回流。

## 核心设计原则

**模型通过工具获取业务事实，不获取 ERP 数据库凭据；业务统计口径由 Java 提供。** 所有数据访问由 Java 侧实时校验权限与主体范围后，以只读聚合接口返回结构化事实；Python 工作流用 Pydantic（extra=forbid）校验数据契约；口径限制说明（LIMITATION）由 Java 统一生成下发，LLM 仅对事实做文案汇总。

**工具令牌绑定发起人。** Python 回调取数时携带 Java 签发的短时令牌（HMAC，含用户标识与过期时间，5 分钟有效）。
工具网关还要求「仅本机来源 + 共享密钥匹配」，因此即使 AI 服务被他人直接访问，也无法伪造身份取走别人的数据。

## 功能清单

### AI 助手对话

- 自然语言问答，模型自行决定调用哪些工具、需要什么筛选条件，多轮取数后汇总作答
- 可用数据：订单、退款、库存、出入库、采购、物流、商品、SKU、会员、供应商、仓库、店铺（全部只读）
- Java 只负责组装上下文、保存会话历史与转发流式事件；AI 服务不可用时返回可读提示，不留下空白流

### 经营分析助手（多主题并行）

- 用户自然语言提问，LLM 任务规划器按问题路由到销售、财务、售后、库存主题（不支持的问题显式返回 unsupported，不猜测）
- `Send` API 将可用主题节点**同一超步并行执行**（fan-out），`operator.add` Reducer 聚合各节点状态，按固定业务顺序排序后生成经营报告
- 数据覆盖：本期/上期销售对比、支付与退款差额、已结算订单利润、SKU 表现排行（含退款归集、四象限、TOP5/10/20 集中度）、负利润订单及诱因分布、多店对比、库存风险分布
- 可选接入 LLM 生成结论文案（`useModel` 显式开启），关闭时输出纯规则汇总

### 明细导出

- SKU 表现明细、负利润订单明细导出 CSV（UTF-8 BOM、列白名单、5000 行上限截断提示）
- 导出与查询走完全相同的权限校验，不含任何买家个人信息

### 库存补货审核（人机闭环）

- AI 汇总库存与销量资料生成补货建议，`interrupt` 挂起等待人工审核，checkpoint 持久化（服务重启可恢复）
- 人工确认后流程恢复，生成采购草稿进入既有采购流程；草稿创建幂等且与记录同一事务提交
- 多进程经数据库会话锁串行化处理同一审核任务
- 产品定位：**AI 汇总资料、人决定补货**——审核人与采购流程是权威来源

### 商品文案优化

- 基于 Java 商品资料生成 Listing 草稿（标题、卖点、描述、关键词），按站点规则检查（标题长度、禁用词），草稿需人工确认后才可使用

## 模型配置

- LLM 在「AI 智能 > 模型配置」页面配置（OpenAI 兼容接口），后端调用本服务时经请求头透传模型地址、密钥与模型名；
  对话、深度分析、工作台简报与「测试连接」共用这一处配置，Java 侧只做透传，不构造模型客户端；
  页面未配置时回退到环境变量 `AI_MODEL_ENABLED`、`AI_MODEL_NAME`、`AI_MODEL_API_KEY`、`AI_MODEL_BASE_URL` 与 `config.local.json` 的 `model` 段
- 未配置或未启用模型时，部分确定性查询与规则汇总仍可使用；模型对话和模型生成能力需要有效配置。页面传入的模型配置优先于 Python 环境变量中的启用设置。
- 服务间调用使用 `ERP_AGENT_SECRET` 鉴权
- 详细启动步骤见 [部署指南](部署指南.md)

## 审核检查点并发边界

ERP 已提交的审核状态是业务权威来源，Python 检查点用于恢复工作流。PostgreSQL 检查点模式通过按任务 ID 的数据库会话锁协调多进程；SQLite 模式通过同目录独立锁库的 BEGIN IMMEDIATE 串行化完整恢复过程，支持同机多个 worker；锁库文件必须与检查点文件一起放在同一个本地持久化目录，不要删除或为不同 worker 配置不同路径。SQLite 的不同任务仍串行恢复，适合本地开发和低吞吐单机部署；多机部署使用 PostgreSQL，按任务会话锁允许不同任务并发。

## 对话输入范围

发送对话时消息不能为空，单条消息最多 8000 个 Java 字符，会话标识最多 64 个字符；超过范围在保存记录及调用模型前拒绝。该限制属于输入保护，不是精确 Token 计量或费用配额。

会话标识通过独立会话归属表唯一绑定用户。消息保存和删除在同一事务中确认归属并加锁；历史读取及发送给模型的上下文按用户过滤。旧会话首次写入时校验历史归属，混合用户或无归属历史拒绝访问；删除消息后仍保留会话归属，避免标识被其他用户重新占用。已有数据库先执行 `docker/mysql/upgrade-ai-session-access.sql`。

模型上下文从数据库读取当前用户最近 40 条消息，按时间与 ID 稳定排序；历史查询默认返回最近 50 条，最多 100 条，可同时传 beforeTimestamp 与 beforeId 读取更早内容。会话列表返回最近 100 个会话，在数据库分组，不全量读取消息。已有库执行一次 `docker/mysql/upgrade-ai-history-index.sql` 补充上下文索引。

## 运行保护与费用边界

付费模型调用由 Java 的统一准入控制。默认每个请求预占 220000 Token；用户、商户和系统每日预算分别为 1000000、3000000 和 10000000 Token；付费请求每分钟分别限制 10、30、60 次，在途分别限制 2、4、8 个。额度、频率、在途状态和结算记录保存在 MySQL，多个 Java 实例共享。数据库不可用时拒绝新的模型调用，不默认放行。

公共 AI 入口另有入库前频率保护：每用户每分钟 60 次、系统 300 次；请求体最多 512 KiB。规则分析不预占付费预算，但仍受入口资源边界约束。每个 Java 实例的公共 AI 请求最多在途 4 个，工具回调另有 4 个名额；SSE 名额保持到异步请求结束，回调名额独立以避免相互等待。超过限制直接拒绝，人工暂停入口与配置维护保留可用。数据库共享的付费并发限制在此之外继续生效。显式关闭 useModel 的已知规则接口不会调用模型；模型配置检查也属于受控付费入口。

Python 所有模型入口共用资源策略：默认最多 4 次模型调用和 8 次工具调用，每次输入最多 12000 字符，累计输入最多 48000 字符，每次输出最多 1024 Token；模型单次超时最多 20 秒，请求期限为 90 秒，工具循环也有递归上限。Java 和 Python 都只保留有界近期聊天上下文。字符限制和预算预占不是精确的 Token 计数，模型服务商的计费规则仍需单独核对。

模型返回真实 usage 时按实际输入、输出 Token 结算，多次结算同一请求不会重复扣减。用量缺失、超时或断连时保留预占并标记待核对，不能利用断连无条件退回额度。过期在途租约释放并发名额，但不返还不明费用。默认租约为 180 秒。预算是 Token 预算，不是人民币费用账单；修改 Python 输出或调用上限时，应同步评估 Java 的预占额度及服务商额度。

连续 3 次上游故障触发 30 秒熔断，之后只允许有租约的恢复探测。鉴权、参数和额度拒绝不做多层自动重试。浏览器结束 SSE 会取消对应工作线程并关闭 Java 到 Python 的连接，Python 在断连后停止后续模型和工具步骤；已经开始的服务商调用仍可能计费，未确认用量按待核对处理。

流式事件必须符合 NDJSON 协议；缺少完成事件、异常文本、单行超过 64 KiB或累计输出超过 32000 字符，均不能冒充完整模型结果保存。模型部分输出出错时不作为完整助手回答加入会话。

## 运行管理与排查

在「AI 智能 → 模型配置 → 总部运行保护」可刷新受控请求数、已确认 Token、待核对请求及订单通知积压，并人工暂停或恢复模型调用。此入口要求总部主体及 ai:config:list 权限，每次请求均校验；解除人工暂停不清空预算，也不绕过熔断与并发限制。

Java HTTP、Python、工具回调使用 X-Request-ID 关联。模型、工具和传输日志记录阶段耗时与错误类别，不记录完整提示词、API 密钥或工具令牌。数据库连接池状态可通过运行摘要查看；`scripts/inspect_sql_pressure.py` 只读查看 MySQL 的规范化语句摘要，`scripts/inspect_ai_sales_query.py` 对比指定主体、时间范围的聚合结果与实际执行计划。诊断工具不调用模型。

总部简报按当前模型配置、日期及口径版本短时缓存并合并相同请求；成功结果最多保留 60 秒，降级结果 5 秒，返回生成时间。访问权限在读取缓存前校验，不跨主体共享；配置变化会更换缓存键。非总部账号不使用全局资料生成分析降级摘要；总部摘要也按销售、库存、售后资料权限分别决定是否查询。查询失败明确显示不可用，不等同于业务为零。

## 业务口径评测

`ai-service/evals/business_cases.json` 固定业务题集覆盖结算利润、退款差额、部分库存、售后记录和非法请求契约。在 AI 服务目录执行 `python -m app.evaluate` 进行离线规则评测；可通过 --answers 指定候选回答文件进行口径和禁用断言检查。该命令不调用模型，也不能证明模型整体准确率；规则匹配存在误报和漏报，重要结论仍需人工核对。

## 工具授权与查询资源边界

工具令牌只证明调用身份，不代替资料授权。每次工具回调从数据库读取当前菜单权限及业务主体：销售、售后、会员和店铺查询附加商户、店铺条件；库存查询附加商户、店铺或绑定仓库条件并排除已删除记录；商品查询复用带主体过滤的商品读模型。模型传入的参数不能覆盖这些条件。

采购单、供应商、运单、出入库流水及全局仓库目录沿用总部资料边界；非总部使用对应主体工作台，不能借聊天访问全局列表。所有资料还要求对应 AI 查询权限。会话归属保护历史消息，工具授权保护业务数据，两者分别校验。

工具日期窗口最多 90 天，搜索词最多 100 字，返回条数最多 500（店铺与仓库目录最多 100），格式化资料超过 32000 字符则拒绝并要求缩小范围。列表是受限样本，不能据此声称全量统计；商品查询仅包含授权范围内可见的 SKU。销售 SKU 与库存风险全量统计超过 20000 个 SKU 时明确拒绝，不使用部分行伪造全量结果。

AI MyBatis 读模型单条 SQL 超时为 10 秒，JdbcTemplate 默认查询超时为 10 秒，Redis 池获取等待最多 1 秒。超时用于释放单次执行资源，不保证任何数据量下均能完成，也不替代数据库索引、锁等待排查和服务端容量规划。未知 Token 用量保留待核对，管理摘要与账本供核查使用，不自动猜测服务商最终费用。

## 审核工作流补偿扫描

未同步的审核版本按任务 ID 游标分批轮转，每批最多 20 条；每次尝试都推进游标，到达尾部后回绕。持续失败的前一批任务不会永久挡住后面的任务；进程重启从头扫描，游标仅用于公平调度，不代表任务已同步。只有 Python 成功返回后才按当前版本标记同步，失败仍保留在数据库中。

工作线程中断或取消时停止本轮，不继续发起新的外部同步。该扫描不是分布式租约或指数退避，多实例仍可能重复同步，依靠工作流版本和幂等契约保证业务事实不重复。
