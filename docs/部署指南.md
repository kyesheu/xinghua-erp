# 部署指南

本地开发部署步骤。项目为前后端分离的三部分：Java 后端（`erp-backend/erp-api`，端口 6149）、Vue 前端（`erp-frontend/`）、Python AI 服务（`ai-service/`，端口 8000）。

## 一、环境要求

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| JDK | 21 | 后端编译与运行 |
| Maven | 3.9+ | 后端构建 |
| Node.js | 18+ | 前端构建与开发服务 |
| Python | 3.12 | AI 服务 |
| Docker | — | 基础设施（MySQL/Redis/MinIO/RabbitMQ） |

## 二、启动基础设施

在 `docker/` 目录下执行：

```bash
docker compose up -d
```

包含的服务与端口（均只绑定本机）：

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| MySQL 8.0 | 13370 | 首次启动自动导入 `docs/sql/xinghua-erp.sql`（仅数据卷为空时），等待健康检查通过 |
| Redis 7.4 | 16379 | 缓存与登录态 |
| MinIO | 19000（API）/ 19001（控制台） | 图片存储，`minio-init` 容器自动创建 `xinghua-erp` 存储桶 |
| RabbitMQ 3.13 | 56720（AMQP）/ 15672（管理台） | 订单异步通知；应用侧 `erp.mq.enabled=false` 时不连接，可按需启动 |

### 数据库迁移脚本（手动执行）

`xinghua-erp.sql` 不含以下表和权限项，连接 `xinghua-erp` 库后按序执行：

1. `docs/sql/business-user-binding-migration.sql` — 账号与业务主体绑定表（权限体系依赖）
2. `docs/sql/ai-inventory-review.sql` — 补货审核任务表
3. `docs/sql/ai-purchase-draft.sql` — 采购草稿幂等记录表
4. `docs/sql/ai-agent-permissions.sql` 及 `ai-*-permission.sql`、`ai-finance-settlement.sql` — AI 相关权限项登记（仅创建权限，不自动授权）
5. `docs/sql/erp_logistics_company-data.sql` — 物流公司基础数据（可选，全量覆盖导入）

## 三、启动后端

```bash
mvn -f erp-backend/pom.xml clean install
# 运行 erp-api（端口 6149），可在 IDEA 直接启动，或：
java -jar erp-backend/erp-api/target/erp-api-4.1.0.jar
```

关键环境变量（凭据类均有仅供本地开发的默认值，生产环境必须显式覆盖，仓库内不含任何真实密码）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_PASSWORD` | xinghua-erp-dev-only | MySQL 连接密码，需与 `docker/docker-compose.yml` 的 `MYSQL_ROOT_PASSWORD` 一致 |
| `TOKEN_SECRET` | 本地开发占位值 | JWT 签名密钥，生产环境必须替换为足够长的随机串 |
| `DEEPSEEK_API_KEY` | 空 | 后端 DeepSeek 密钥，不设置时 AI 能力自动降级 |
| `ERP_MQ_ENABLED` | false | 开启后连接 RabbitMQ 发布订单事件 |
| `ERP_AGENT_URL` | http://127.0.0.1:8000 | Python AI 服务地址 |
| `ERP_AGENT_SECRET` | — | 与 AI 服务约定的共享密钥（≥32 字符），不设置或过短时 AI 内部接口返回 403 |
| `MINIO_*` | 见 application.yml | MinIO 地址与凭据（默认 `minioadmin` / `minioadmin`） |

示例：`export DB_PASSWORD=xinghua-erp-dev-only MYSQL_ROOT_PASSWORD=xinghua-erp-dev-only TOKEN_SECRET="$(openssl rand -hex 32)"`

容器化运行：`docker/docker-compose.yml` 中 `backend` 段有完整注释模板，先 `mvn -pl erp-api -am clean package -DskipTests` 再取消注释启动。容器编排与配置映射（MySQL 自定义配置、nginx 部署配置）见 [docker/README.md](../docker/README.md)。

## 四、启动前端

```bash
cd erp-frontend
npm install
npm run dev
```

浏览器访问前端地址，后端 API 指向 `http://localhost:6149`（`VITE_APP_BASE_API`）。

## 五、启动 AI 服务

```bash
cd ai-service
python -m venv .venv
.venv/Scripts/pip install -e .        # Windows；Linux/macOS 用 .venv/bin/pip
.venv/Scripts/uvicorn app.main:app --port 8000
```

配置（环境变量或 `ai-service/config.local.json`）：

| 变量 | 说明 |
| --- | --- |
| `ERP_AGENT_SECRET` | 与后端一致，否则内部接口 403 |
| `AI_MODEL_ENABLED` | false（默认）时全部功能走纯规则路径，不需要任何模型密钥 |
| `AI_MODEL_NAME` / `AI_MODEL_API_KEY` / `AI_MODEL_BASE_URL` | 启用 LLM 时的 OpenAI 兼容接口配置 |

**无模型也能跑**：`AI_MODEL_ENABLED=false` 时任务规划与文案生成使用确定性规则，AI 各功能仍可完整验证，适合演示与离线测试。

## 六、图片存储（MinIO）

`minio-init` 容器会自动创建 `xinghua-erp` 存储桶，并允许匿名读取 `images/`、`supplier-license/`、`avatar/`、`goods/` 分类目录的图片，其他操作需要密钥。数据保存在 `minio-data` 数据卷，`docker compose down` 不会删除图片。

## 七、验证部署

1. 前端登录进入工作台，切换总部/商户/店铺账号观察数据范围变化
2. 商品 → 订单 → 库存页面正常加载（演示库自带示例数据）
3. AI 页面在模型未启用时展示规则汇总文案
4. （可选）`erp.mq.enabled=true` 且 RabbitMQ 启动后，订单同步可在 15672 管理台看到 `erp.order.created` 队列消息
