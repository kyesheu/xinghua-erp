# 部署指南

本地开发部署步骤。项目为前后端分离的三部分：Java 后端（`erp-backend/erp-api`，端口 6149）、Vue 前端（`erp-frontend/`）、Python AI 服务（`ai-service/`，端口 8000）。

## 一、环境要求

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| JDK | 21 | 后端编译与运行 |
| Maven | 3.9+ | 后端构建 |
| Node.js | 18+ | 前端构建与开发服务 |
| Python | 3.12 | AI 服务 |
| Docker | — | 基础设施（MySQL/Redis/MinIO/RabbitMQ） |

## 二、启动基础设施

在 `docker/` 目录下执行：

```bash
docker compose up -d
```

包含的服务与端口（均只绑定本机）：

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| MySQL 8.0 | 13370 | 首次启动自动按序执行 `docs/sql/` 下的 10 个初始化脚本（仅数据卷为空时），等待健康检查通过 |
| Redis 7.4 | 16379 | 缓存与登录态 |
| MinIO | 19000（API）/ 19001（控制台） | 图片存储，`minio-init` 容器自动创建 `xinghua-erp` 存储桶 |
| RabbitMQ 3.13 | 56720（AMQP）/ 15672（管理台） | 订单异步通知；应用侧 `erp.mq.enabled=false` 时不连接，可按需启动 |

### 数据库初始化（容器自动执行）

MySQL 容器首次启动时会按文件名顺序执行 `/docker-entrypoint-initdb.d` 下的脚本，**不需要手工导库**：

| 顺序 | 脚本 | 内容 |
| --- | --- | --- |
| 01 | `xinghua-erp.sql` | 主库结构 + 基础数据（145 张表、菜单与权限种子） |
| 02 | `ai-inventory-review.sql` | 补货审核任务表 `ai_inventory_review_task` |
| 03 | `ai-purchase-draft.sql` | 采购草稿幂等记录表 `ai_purchase_draft_request` |
| 04 | `business-user-binding-migration.sql` | 账号与业务主体绑定表 `erp_business_user_binding` |
| 05–09 | `ai-agent-permissions.sql` 等 | AI 相关权限项登记（只创建权限，不自动授权） |
| 10 | `ai-finance-settlement.sql` | 财务结算权限项 |

初始化完成后即可用管理员账号登录：账号 `admin`，初始密码 `admin123`。该密码由种子数据写入 `sys_user`，正式部署后请立即修改。

这些脚本均为幂等写法（`IF NOT EXISTS` / `NOT EXISTS`），重复执行不会报错。`erp_logistics_company-data.sql` 未挂载：物流公司数据已包含在主 SQL 内，单独导入反而会覆盖。

两个必须注意的点：

- **只在数据卷为空时执行**。改过 SQL 之后必须 `docker compose down -v && docker compose up -d` 才会重新导入，否则容器沿用旧数据卷、看不到任何变化。
- **健康检查会校验关键表**。`sys_message`、`sys_user`、`ai_config`、`ai_inventory_review_task` 四张表缺任意一张，mysql 会停在 `unhealthy` 而不是报告健康——此时用 `docker logs xinghua-erp-mysql-1 | grep -i error` 查导入中断原因。

## 三、启动后端

```bash
mvn -f erp-backend/pom.xml clean install
# 运行 erp-api（端口 6149），可在 IDEA 直接启动，或：
java -jar erp-backend/erp-api/target/erp-api-4.1.0.jar
```

关键环境变量（凭据类均有仅供本地开发的默认值，生产环境必须显式覆盖，仓库内不含任何真实密码）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_PASSWORD` | xinghua-erp-dev-only | MySQL 连接密码，需与 `docker/docker-compose.yml` 的 `MYSQL_ROOT_PASSWORD` 一致 |
| `TOKEN_SECRET` | 本地开发占位值 | JWT 签名密钥，生产环境必须替换为足够长的随机串 |
| `ERP_MQ_ENABLED` | false | 开启后连接 RabbitMQ 发布订单事件 |
| `ERP_AGENT_URL` | http://127.0.0.1:8000 | Python AI 服务地址 |
| `ERP_AGENT_SECRET` | — | 与 AI 服务约定的共享密钥（≥32 字符），不设置或过短时 AI 内部接口返回 403 |
| `MINIO_*` | 见 application.yml | MinIO 地址与凭据（默认 `minioadmin` / `minioadmin`） |

**大模型密钥不在环境变量里配置**：启动后登录系统，进入「AI 智能 > 模型配置」新增一条配置，填写
API 地址（兼容 OpenAI 协议，如 `https://api.deepseek.com/v1`）、API 密钥与模型名称，启用并设为默认。
密钥保存在 `ai_config` 表，Java 侧分析与 Python 服务工作流共用这一处配置（后端调用 AI 服务时经请求头透传），
保存后可点「测试」按钮验证连通性。无需设置 `DEEPSEEK_API_KEY`，也无需修改 `ai-service/config.local.json` 的 `model` 段
（该段仅作为页面未配置时的回退）。

示例：`export DB_PASSWORD=xinghua-erp-dev-only MYSQL_ROOT_PASSWORD=xinghua-erp-dev-only TOKEN_SECRET="$(openssl rand -hex 32)"`

以上环境变量也可以不用，改为本机配置文件：把 `erp-backend/erp-api/src/main/resources/application-dev.yml.example`
复制成同目录下的 `application-dev.yml` 再填写。该文件已被 `.gitignore` 排除，不会入库；
`spring.profiles.active` 默认为 `dev`，存在该文件时自动叠加，不存在时也能正常启动。

**启动不依赖模型密钥**：Java 侧不装配模型客户端，模型构建、工具循环与流式输出全部在 `ai-service` 完成。因此全新部署、尚未配置任何模型时后端可以正常启动，
只是对话与分析功能会给出「请先配置模型」的提示，不会因缺少密钥而启动失败。

容器化运行：`docker/docker-compose.yml` 中 `backend` 段有完整注释模板，先 `mvn -pl erp-api -am clean package -DskipTests` 再取消注释启动。容器编排与配置映射（MySQL 自定义配置、nginx 部署配置）见 [docker/README.md](../docker/README.md)。

## 四、启动前端

```bash
cd erp-frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:88`，后端 API 指向 `http://localhost:6149`（`VITE_APP_BASE_API`）。

## 五、启动 AI 服务

```bash
cd ai-service
python -m venv .venv
.venv/Scripts/pip install -e .        # Windows；Linux/macOS 用 .venv/bin/pip
.venv/Scripts/uvicorn app.main:app --port 8000
```

需要跑测试时装上测试依赖：`.venv/Scripts/pip install -e ".[test]"`（额外包含 pytest 与 httpx）。

配置（环境变量或 `ai-service/config.local.json`）：

| 变量 | 说明 |
| --- | --- |
| `ERP_AGENT_SECRET` | 与后端一致（至少 32 位），否则内部接口 403 |
| `ERP_BACKEND_URL` | 后端地址，默认 `http://127.0.0.1:6149`；AI 服务的工具调用经此回查业务数据 |
| `AI_MODEL_ENABLED` | false（默认）时全部功能走纯规则路径，不需要任何模型密钥 |
| `AI_MODEL_NAME` / `AI_MODEL_API_KEY` / `AI_MODEL_BASE_URL` | 启用 LLM 时的 OpenAI 兼容接口配置，页面配置优先于此 |

**无模型也能跑**：`AI_MODEL_ENABLED=false` 时任务规划与文案生成使用确定性规则，AI 各功能仍可完整验证，适合演示与离线测试。

## 六、图片存储（MinIO）

`minio-init` 容器会自动创建 `xinghua-erp` 存储桶，并允许匿名读取 `images/`、`supplier-license/`、`avatar/`、`goods/` 分类目录的图片，其他操作需要密钥。数据保存在 `minio-data` 数据卷，`docker compose down` 不会删除图片。

## 七、验证部署

1. 用管理员账号登录，进入工作台
2. 系统管理里创建商户与店铺，商品管理里建立品牌、类目、商品与 SKU（初始化库只含菜单、权限与物流公司等基础数据，商品与订单为空）
3. 新建商户、店铺账号并绑定业务归属，分别登录观察数据范围差异
4. AI 页面在模型未启用时展示规则汇总文案
5. （可选）`erp.mq.enabled=true` 且 RabbitMQ 启动后，订单同步可在 15672 管理台看到 `erp.order.created` 队列消息
