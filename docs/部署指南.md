# 部署指南

本指南用于在本机首次启动系统。所有命令均以仓库根目录为起点，带有 `cd` 的步骤请分别在新的终端执行。

## 环境与服务

准备 JDK 21、Maven 3.9 或以上、Node.js 22.12 或以上、Python 3.12 和 Docker Compose。前端使用 Vite 8，应使用支持它的 Node.js 版本。

| 服务 | 默认地址或宿主端口 | 用途 |
| --- | --- | --- |
| 前端 | http://localhost:88 | 管理页面 |
| Java 后端 | http://localhost:6149 | 业务 API |
| Python AI | http://127.0.0.1:8000 | AI 工作流 |
| MySQL | 127.0.0.1:13370 | 业务数据库 |
| Redis | 127.0.0.1:16379 | 缓存与登录态 |
| MinIO | 19000 / 19001 | 文件 API / 管理控制台 |
| RabbitMQ | 56720 / 15672 | AMQP / 管理控制台 |

## 1. 启动基础设施

```powershell
cd docker
docker compose up -d
docker compose ps
```

等待 MySQL 健康检查通过后再启动后端。首次创建空数据卷时，Compose 按编号执行挂载的初始化 SQL，并创建 MinIO 存储桶。初始化过程见[容器说明](../docker/README.md)。

`docs/sql/xinghua-erp.sql` 包含建表和基础数据，也包含删除重建表的语句，只用于新库初始化。已有数据库应按差异升级，不能通过重新导入主 SQL 或删除数据卷来更新结构。

已有数据库缺少订单 Outbox 表或消息去重字段时，执行一次 `docker/mysql/upgrade-order-reliability.sql`。该脚本含一次性 ALTER TABLE，不应重复执行；执行前备份数据库并确认当前表结构。

## 2. 配置并启动后端

本地配置模板为 `erp-backend/erp-api/src/main/resources/application-dev.yml.example`。可复制为同目录的 `application-dev.yml`，填写本机配置；该文件不会提交到 Git。默认启用 `dev` 配置。

| 配置 | 用途 |
| --- | --- |
| `MYSQL_ROOT_PASSWORD` / `DB_PASSWORD` | 容器与后端的数据库密码，必须一致 |
| `TOKEN_SECRET` | JWT 签名密钥 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 对象存储凭据 |
| `ERP_MQ_ENABLED` | 是否开启订单 MQ 通知，默认 `false` |
| `ERP_AGENT_URL` | Python 地址，默认 `http://127.0.0.1:8000` |
| `ERP_AGENT_SECRET` | Java 与 Python 共用的服务密钥，至少 32 个字符 |

仓库配置中的默认数据库和存储凭据仅供本机使用。对外部署时需替换凭据与签名密钥，限制基础设施访问范围。

```powershell
mvn -f erp-backend/pom.xml -pl erp-api -am clean package
java -jar erp-backend/erp-api/target/erp-api-4.1.0.jar
```

## 3. 启动前端

```powershell
cd erp-frontend
npm install
npm run dev
```

访问 http://localhost:88。开发环境的 API 和 SSE 地址由 `.env.development` 配置。静态部署与反向代理见[前端说明](../erp-frontend/README.md)。

## 4. 首次登录

新库初始化管理员账号为 `admin`，初始密码为 `admin123`。登录后先修改密码，再建立商户、店铺、仓库、商品和 SKU。初始化基础数据与可选的[演示数据](../docker/seed/README.md)是两套内容，业务数据以实际导入内容为准。

创建员工账号后，分别配置角色权限和业务归属。账号能否执行操作取决于两者，见[账号权限与数据范围](业务账号权限与数据范围.md)。

## 5. 启动 AI 服务

在后端和 Python 服务的终端中设置相同的 `ERP_AGENT_SECRET`。Python 的 `ERP_BACKEND_URL` 指向 Java 地址。

```powershell
cd ai-service
python -m venv .venv
.venv/Scripts/pip install -e .
.venv/Scripts/uvicorn app.main:app --port 8000
```

模型在「AI 智能 → 模型配置」页面维护：填写兼容 OpenAI 协议的地址、密钥和模型名，启用并设为默认。页面提供连接检查入口，使用时会实际访问所配置的模型服务，是否计费由服务商决定。

页面配置优先于 Python 的环境变量和 `config.local.json` 回退配置。未配置模型不影响 Java 启动；确定性资料查询与部分规则汇总可使用，依赖模型的对话与分析需完成模型配置，不能将规则结果视为模型分析。

审核检查点默认使用 SQLite；`ERP_AGENT_CHECKPOINT_DB` 可指定文件路径。同机 worker 应共享该文件和同目录锁库文件。多机部署使用 `ERP_AGENT_CHECKPOINT_POSTGRES_DSN`，并在 AI 服务目录执行 `python -m app.setup_checkpoints` 初始化检查点表。具体边界见[AI 智能体说明](AI智能体说明.md)。

## 6. 配置外部能力

- 平台商品、订单和售后调用需要有效的平台应用凭据、权限及店铺授权。
- 电子面单需要对应平台和物流账户配置。
- MQ 通知需要启动 RabbitMQ，并设置 `ERP_MQ_ENABLED=true`；关闭期间不会记录或补发历史订单创建事件。
- 外部通知需要启用渠道并填写 Webhook，见[消息说明](消息与外部通知设计.md)。

## 常见情况

| 现象 | 检查内容 |
| --- | --- |
| MySQL unhealthy | 执行 `docker compose -f docker/docker-compose.yml logs mysql`，检查初始化错误和缺失表 |
| 页面无法登录 | 后端是否运行、前端 API 地址是否正确、账号是否启用 |
| 菜单或数据不可见 | 当前角色权限、业务归属和主体状态 |
| AI 内部接口返回 403 | 两端共享密钥是否相同、是否达到长度要求 |
| Python 无法取数 | 回调地址是否可达、服务密钥及工具令牌是否有效 |
| 图片无法访问 | MinIO 地址、存储桶和对应目录读策略 |
| 店铺拉取失败 | 应用权限、店铺授权状态及平台返回信息 |

## 已有环境的 AI 增量结构

升级前备份数据库，先在项目根目录执行 `ai-service/.venv/Scripts/python.exe scripts/upgrade_local_ai.py` 检查；确认目标是本地数据库后加 --apply 应用缺失的会话归属、预算与调用账本、熔断开关、Outbox 租约及查询索引。工具检查实际列和索引，不删除重建业务表。默认容器名为 xinghua-erp-mysql-1，可用 --container 指定实际容器。

新库直接使用主初始化 SQL，不再重复执行同名索引和 ALTER TABLE 脚本。Java 运行保护的 erp.ai.* 配置提供预算、付费频率和并发默认值；Python 用 ERP_AI_MAX_MODEL_CALLS、ERP_AI_MAX_TOOL_CALLS、ERP_AI_MAX_INPUT_CHARS、ERP_AI_REQUEST_INPUT_CHARS、ERP_AI_MAX_OUTPUT_TOKENS、ERP_AI_REQUEST_SECONDS 调整模型边界。两端上限、Java 预占及租约要一起评估，不应只扩大输出上限。

对账查询诊断可使用 `python scripts/inspect_reconciliation_query.py --inventory-id 具体库存ID` 只读比较聚合计划；`python scripts/benchmark_reconciliation.py` 自动创建并清理独立临时库进行50000条批次规模验证，需要本地MySQL建库权限，不修改业务库。不能将隔离样本耗时当作生产性能承诺。
