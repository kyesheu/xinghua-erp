# 业务账号归属与数据范围

`sys_user.user_type` 表示账号类型，业务主体通过 `erp_business_user_binding` 绑定；部门 ID 用于组织管理。总部账号无需绑定，商户、店铺、供应商及仓库账号分别绑定对应主体。店铺范围同时包含所属商户和店铺；总部自营使用 `merchant_id=0`。

总部账号在用户管理的“业务归属”中配置或停用绑定。服务端每次读取账号、绑定和主体状态，变更后下次请求生效；未绑定或主体不可用时拒绝已接入功能。用户表示已创建绑定表，现有账号未自动绑定。

## 实现与待完善

- 已接入：首页看板、本地售后、店铺售后列表、内部退款列表、售后处理列表、主系统库存列表及批次查询、入出库单列表详情和操作、AI 库存采购只读接口。库存查询中的店铺账号只看店铺独立库存，仓库账号只看绑定仓库，供应商账号不开放。
- 采购订单、物流和助手草稿目前仅向具有相应实时权限的总部账号开放；非总部账号采购尚未开放。采购承运商目录（`/api/erp-api/erp/logistics`）同样仅限总部：读取接受 `purchase:order:query` 或 `purchase:logistics:manage` 任一，写入（新增、修改、启停、删除）只认 `purchase:logistics:manage`，权限变更下次请求即生效。供应商档案（`/api/erp-api/supplier`）的写入（`POST`/`PUT`/`DELETE`）要求 `purchase:supplier:manage` 且仅限总部；读取接口尚未接入权限与主体范围，任何已登录账号仍可读取供应商列表与详情，待下游页面权限梳理后再收紧。其他售后详情、平台操作、订单、发货、其他库存、批量和导出等接口仍待接入主体范围。供应商代发暂限总部。
- 入出库和库存查询需单独的 `wms:inventory:query`、`wms:stockin:query/operate`、`wms:stockout:query/operate` 权限，按服务端主体限制数据范围；旧手工创建入出库单暂仅总部支持。权限登记脚本为 `docs/sql/ai-agent-permissions.sql`，已在本地库登记权限项，尚未给角色授权；需要管理员按岗位授权。绑定接口标注 `system:user:edit`；当前未发现启用方法安全的配置。`checkUserDataScope` 使用的查询未见数据范围切面，权限注解及用户数据范围需要验证和完善。新登录不再默认给予所有账号通配权限；AI 接口单独实时读取角色菜单权限，已删除或停用角色不授予权限，历史登录缓存需重新登录。

验收需覆盖多个商户、店铺、供应商和仓库，检查绑定及主体停用、变更、总部自营，以及伪造 ID 对列表、详情和操作的影响。绑定解析和管理已用隔离 H2 验证；真实环境和完整跨角色隔离仍待验收。

## 登录连接失败后的恢复
登录验证信息加载失败时，页面保留账号和密码输入，显示重新加载入口并禁止提交；后端恢复后点击重新加载即可恢复登录，不需要刷新页面。该操作不关闭验证码或绕过验证。前端类型检查和真实浏览器断开/恢复后端验证通过。
