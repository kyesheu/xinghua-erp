# 业务账号权限与数据范围

系统在 RBAC 接口权限之外，再叠加一层业务主体数据范围：同一个接口，不同账号只能读写自己主体范围内的数据。

## 首次分配账号

1. 由总部管理员创建用户并分配岗位角色。
2. 在用户的业务归属中选择账号类型及绑定主体。
3. 确认用户、角色和主体均启用后再交付账号。

角色决定可执行的功能，业务归属决定可操作的数据范围；两者同时满足才可访问。

## 账号类型与主体绑定

`sys_user.user_type` 表示账号类型，业务主体通过 `erp_business_user_binding` 绑定，部门 ID 只用于组织管理。

| 账号类型 | 绑定主体 | 数据范围 |
| --- | --- | --- |
| 总部 | 无需绑定 | 全部商户与店铺，自营主体为 `merchant_id=0` |
| 商户 | 商户 | 该商户及其下所有店铺 |
| 店铺 | 店铺 | 该店铺 |
| 仓库 | 仓库 | 该仓库的库存与出入库单据 |
| 供应商 | 供应商 | 该供应商相关业务；库存查询不开放 |

绑定在「系统管理 → 用户 → 业务归属」中维护，由总部账号配置或停用。服务端每次请求实时读取账号、绑定与主体状态，修改在下次请求生效；未绑定或主体已停用的账号访问已接入功能时会被拒绝。

## 实现方式

数据范围不由前端传参决定。请求进入后先由 `BusinessSubjectScopeService` 解析当前账号的主体，业务查询再按解析结果在 SQL 条件中追加 `merchant_id` / `shop_id` / `warehouse_id` / `supplier_id` 约束，因此伪造请求参数也取不到范围外的数据。

## 各模块的数据范围

| 模块 | 已按主体范围过滤的接口 |
| --- | --- |
| 首页看板 | 工作台统计 |
| 售后与退款 | 本地售后、店铺售后列表、内部退款列表、售后处理 |
| 库存 | 库存列表、批次查询、入出库单列表与详情、出入库操作 |

库存的附加约束：店铺账号只能看到店铺独立库存，仓库账号只能看到绑定仓库，供应商账号不开放库存查询。

采购与物流只对总部账号开放，非总部账号不提供采购能力：采购单读取需 `purchase:order:query`；承运商目录读取接受 `purchase:order:query` 或 `purchase:logistics:manage`，新增、修改、启停、删除只认 `purchase:logistics:manage`；供应商档案写入需 `purchase:supplier:manage`。出入库与库存查询另需 `wms:inventory:query`、`wms:stockin:query/operate`、`wms:stockout:query/operate`。

## 权限登记与生效时机

权限项由 `docs/sql` 下的权限脚本登记到 `sys_menu`，默认不授予任何角色，需管理员按岗位授权。角色与菜单权限在请求时实时读取，已删除或停用的角色不再授予权限。

AI 会话的归属由独立表唯一绑定用户，发送、历史读取与删除均校验；已存在的混合归属历史拒绝访问。AI 运行摘要及人工暂停功能还要求总部主体与 ai:config:list 权限，不向普通商户开放全局用量和通知积压。

AI 通用工具回调同样按实时菜单权限与数据库主体绑定授权，不能只凭工具令牌访问全局数据。订单、售后、会员、店铺和库存查询各自附带范围条件；商品复用主体过滤读模型。总部专属资料拒绝非总部主体；模型参数、提示词和降级路径均不能扩大账号范围。历史会话所有权与业务数据授权是两个独立边界。

订单结算执行除专用执行权限外，服务端还解析实时商户、店铺范围；逐单事务锁定订单后校验归属，范围外订单不会生成结算单。总部范围不限定商户，供应商和仓库主体不能借执行权限访问销售结算。
